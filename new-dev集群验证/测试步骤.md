# new-dev 安装配置

## 1. 修改哪些字段

当前参数已填写在values-new-dev.local.yaml：集群身份、三个OTLP后端写地址/认证/CA、kubelet CA与节点映射、内存队列及采集namespace范围。通用处理规则使用母目录values-telemetry.yaml，不保留第二份。

本次日志和OTLP允许observability、otel-java-validation；增加业务namespace时同时更新log_namespaces与otlp_namespace_selector。当前persistent_queue=false，不创建PVC；这份配置不要照搬生产。

## 2. 安装命令

在母目录执行：

```bash
shasum -a 256 -c charts/SHA256SUMS

helm upgrade --install otel-operator ./charts/opentelemetry-operator-0.126.1.tgz \
  --kube-context new-dev \
  --namespace opentelemetry-operator-system --create-namespace \
  -f values-operator.yaml --wait --timeout 10m

helm upgrade --install otel-platform ./charts/otel-platform-0.7.5.tgz \
  --kube-context new-dev \
  --namespace observability --create-namespace \
  -f values-telemetry.yaml -f new-dev集群验证/values-new-dev.local.yaml \
  --wait --timeout 10m
```

## 3. 当前资源与访问

- observability：Node6、Cluster1、Gateway/Sampler/Scraper各2、Target Allocator1，共14个平台Pod；两个Instrumentation。
- opentelemetry-operator-system：Operator1个Pod。
- observability-backends：Prometheus、Elasticsearch、Tempo、Grafana、日志适配器及HTTPS入口，共6个Pod。
- otel-java-validation：Java17、Java21及临时jar服务，共3个测试Pod；本次仅清理本地文件，没有删除集群资源。jar服务使用emptyDir，若其Pod重建，已清理的本地构建文件不能用于重新上传；测试应用后续按需另行清理。

后端地址/认证/CA在本目录values-new-dev.local.yaml；Grafana管理员用户名admin，密码在后端访问.local.json的grafana_password。该JSON包含本次其他后端凭据，权限600，不提交或分享。后端安装测试工具已清理，现有后端继续运行。

本地访问Grafana：

```bash
kubectl --context new-dev -n observability-backends port-forward service/grafana 13000:3000 --address 127.0.0.1
```

浏览器打开http://127.0.0.1:13000。生产安装与验收使用母目录部署文档。
